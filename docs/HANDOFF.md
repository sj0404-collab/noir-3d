# Нуар-Дет 3D — передача состояния

Дата: 26.09.2026. Репозиторий: `https://github.com/sj0404-collab/noir-3d`
(ветка `master`, последний коммит `7c53af3`).

Проект — перенос «Нуар-Дета» с three.js на React Three Fiber с приоритетом
качества картинки (PBR, мягкие тени, IBL, пост-обработка) вместо текущего
toon-шейдера. Масштаб — один город Ноктис, стиль сохранён.

## 3. Команды

```bash
cd noir-3d
npm ci

# статика для рендера
npm run build
cd dist && setsid nohup python3 -m http.server 4173 --bind 127.0.0.1 &

# кадр сцены
node tools/capture.mjs "http://127.0.0.1:4173/?az=18&el=8&dist=13&ty=1.5&dpr=1" out.png 1280 720

# модель
node tools/capture.mjs "http://127.0.0.1:4173/?scene=model&clip=Walk&t=0.35&spin=25&dist=3&el=4&ty=0.95&dpr=1" out.png 800 1000

# пересборка модели
/opt/tools/blender/blender -b -P tools/make_detective.py -- --out public/models
```

Параметры URL: `az/el/dist/tx/ty/tz/fov` — камера (`CameraRig`),
`spin/dist/el/ty` — turntable (`Turntable`), `scene=model` — стенд персонажа,
`clip=Idle|Walk|Run|Turn` + `t=0..1` — поза, `dpr`, `probe=1` — диагностика
в `document.title`, `nopost=1`, `flatroad=1`, `loop=demand` — отладочные.

## 4. Состояние модели: v3 (доделать косметику)

**v3 — рабочая модель.** Тело собрано по группам (торс / рука L / рука R /
нога L / нога R), каждая ремешится отдельно вокселем 0.012, веса считаются
только по костям своей группы (`hint` в `skin_character`). Читается как
фигура: раздельные конечности, пропорции ~8 голов, шляпа/ботинки/лупа на местах.

Что было раньше:
- **v1** (капсулы) — персонаж узнаваемый, но «картошка на ножках»: торс-яйцо,
  руки оторваны, пропорции ~5 голов.
- **v2** (конусы + воксельный ремеш всего тела) — **стало хуже**: ремеш с
  вокселем 0.022 запаял руки в торс, а полы пальто (`verts=4`) проглотили ноги.
  Получился цельный бесформенный блоб, который нельзя деформировать.
  Скрин: `model-03.png` (в репозитории не сохранён).
Причина провала v2: ремеш шёл **по всему телу сразу**, из-за чего соседние
части срастались через сустав. Исправлено в v3.

Остатки косметики (не ломают геометрию, видно на скрине model-04):
- полы пальта `CoatTail` — конус 0.168→0.140 от 1.16 до 0.80; из-за широкого
  низа талия читается как юбка. Ужесточить или разбить на переднюю/заднюю
  панель;
- лицо плоское: челюсть и скулы не читаются, шея-воротник даёт notch;
- локти выпирают наружу bulge'ом — уменьшить `Forearm` по толщине;
- ремень скрыт полами.Ещё не сделано: клипы Walk/Run не бесшовные (п.5.2).

## 5. Что делать завтра (в порядке приоритета)

1. **Довести модель v3 до приличного вида** (косметика, без ломки геометрии):
   полы пальто, лицо/челюсть, локти, ремень; затем бесшовные клипы (п.5.2).
2. **Скелет vs анимации**: клипы `Walk` (17 кадров) и `Run` (13) не
   бесшовные — в `anim_walk`/`anim_run` ключи бьются на `n+1` и поза на 1-м
   кадре не совпадает с позой на последнем. Переписать цикл так, чтобы
   кадр `n` совпадал с кадром `0`.
3. **Отдать обещанное пользователю** (это главный незакрытый вопрос):
   - скриншоты модели со всех ракурсов: перед, 3/4, лево, право, зад, сверху
     + крупные планы (голова, кисти, ступня); отдельными PNG **и** одним
     контакт-листом 3×2;
   - видео: отдельный короткий клип на каждую анимацию (Idle/Walk/Run/Turn) —
     mp4 (H.264) + webm, 60 fps, без звука; плюс одно сводное видео
     «поворотный круг 360° + все анимации»;
   - кодировать через ffmpeg из PNG-последовательности
     (`ffmpeg -framerate 60 -i frames/%04d.png ...`);
   - контакт-лист собирается ffmpeg-ом из готовых PNG:
     `ffmpeg -i a.png -i b.png ... -filter_complex hstack/vstack tile=3x2 out.png`.
4. **Довести сцену до Genshin-уровня**: сейчас фасады — голые коробки.
   Нужны модульные фасады (карнизы, пожарные лестницы, кондиционеры, вывески),
   LOD, ветер-анимация флагов, толпа с LOD.
5. **Карта порта фич** из three.js-версии (`nuar-det` v1.11.0) в R3F —
   ещё не составлена.

## 6. Грабли, на которые уже наступили (не повторять)

- `<Environment>` из drei в headless-прогоне **оставляет render target
  привязанным** — сцена уходит в cubemap и кадр выходит пустым. Отсюда
  `ProceduralEnv` со сбросом `gl.setRenderTarget(null)`.
- `useFrame` с `priority > 0` **отключает авто-рендер** в R3F (так работает
  `EffectComposer`). Диагностический `RenderProbe` с priority 2/3 из-за этого
  гасил сцену.
- `gl.info.render.calls` читается **до** рендера кадра — как метрика пустого
  кадра бесполезен. Правду даёт `readPixels` после композита.
- `chromium --screenshot` с `--virtual-time-budget` может снять **недоприсованный
  буфер** (получились пустые кадры). Надёжен только Playwright с ожиданием
  `window.__ready`.
- `page.screenshot()` по умолчанию таймаутится 30 c — на SwiftShader кадр не
  успевает; нужен `timeout: 180000`.
- Тяжёлые кадры: 5 теневых point-light'ов = 30 проходов кубических карт.
  Держать максимум один. `dpr` в headless — строго 1.
- Двойной tone-mapping (renderer + эффект пост-обработки) даёт цвета
  вроде маджентовых окон. В `App.tsx` стоит `NoToneMapping`, ACES живёт
  только в `Post`.
- Сервер надо поднимать через `setsid nohup ... &`, иначе он умирает вместе
  с shell-командой агента.
- `PCFSoftShadowMap` в three 0.186 удалён (предупреждение в консоли).
